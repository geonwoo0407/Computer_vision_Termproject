# SeatSense 팀 작업 분담

6조 「열람실 장기간 좌석이탈 및 미예약 이용 방지 시스템」 제안서 §1.2, §2.1, §3, §4 및 §6을 기준으로 한다. 앱에는 288석이 있고, 제안서의 첫 실험 규모는 앞뒤 카메라가 함께 보는 3~5석이다. 시연 좌석 번호와 확장 범위는 설치 후 팀이 정한다.

| 작업 | 시작점 | 다음 담당에게 전달할 결과 |
|---|---|---|
| 김건우 · RGB-D 객체 검출 및 영상처리 | 카메라별 RGB, 정렬된 깊이, 고정한 빈 책상 | 카메라별 YOLO 검출 로그, 상판 변화 후보, 동일 장면의 정답표 |
| 보정·추적 · 제안서의 조예인(보정), 최고운별(추적·소지품 연관) 업무 | 두 시리얼의 검출 로그, 내부 파라미터, 보드와 좌석 대응점 | 보정 파일과 검증 오차, 익명 추적 ID, 좌석별 관측과 불확실성 |
| 판단·앱·LED · 제안서의 이승엽(좌석 상태·앱), 조예인(하드웨어) 업무 | 시간순 좌석 관측, 모의 예약 DB | 좌석 상태 전이, 예약 가능 여부, 실시간 화면, 좌석별 LED 명령과 결과 |

### 건우가 먼저 준비할 것

1. 팀원 두 명이 앞뒤 카메라에 함께 보이는 좌석을 골라 빈자리 → 착석 → 옆자리로 가방 이동 → 한쪽 시야 가림 → 복귀 → 짐을 들고 퇴실하는 장면을 촬영한다. 정상 예약과 미예약은 같은 영상에 다른 모의 예약을 적용해 비교할 수 있다. 실제 열람실 촬영은 제안서대로 허가를 받고 진행한다.
2. 장면별로 시각, 좌석 번호, 실제 착석, 짐의 위치, 짐을 옮긴 사람의 실험용 번호, 어느 시야가 가렸는지를 기록한다. 빈 의자 이동과 미등록 소지품도 넣는다. 동일 장면에서 YOLO11n/26n의 사람·짐 누락과 오검출을 확인하고, 설정을 조정한 영상과 평가 영상을 나눈다.
3. YOLO가 알아보는 소지품은 클래스와 박스를 넘긴다. 담요처럼 이름을 못 붙여도 상판 차분·임계값·모폴로지로 얻은 변화 후보를 넘긴다. 의자 자체가 움직인 상황과 의자 위에 가방이 놓인 상황은 별도로 평가한다. 유효한 깊이만 미터 단위로 넘긴다.

### 데이터 전달

- **건우 → 보정·추적.** `main.py --jsonl`의 한 줄은 한 카메라의 한 프레임이다. `serial_number`, `frame_id`, `timestamp_domain`, `capture_monotonic_s`, `detections`를 읽는다. 객체에는 `class_name`, `confidence`, `bbox`(픽셀 xyxy), `position_3d_m`(해당 RGB 광학 좌표계)가 있다. `--stereo`로 보정을 적용하면 `position_common_m`은 첫 번째 카메라 좌표계다. `null`은 깊이를 알 수 없다는 뜻이다. 좌석 후보는 해당 시점에서 보정한 ROI가 있을 때 활용한다. 반대 시점에 같은 픽셀 ROI를 복사하면 안 된다.
- **시간 맞추기.** 같은 PC·같은 실행에서 두 RealSense 프레임의 `capture_monotonic_s`(호스트 수신 시각, 초)를 비교한다. 하드웨어 동기화에는 별도 검증이 필요하다. 기존 로그에는 이 필드가 없을 수 있다. RGB 동영상은 `timestamp_domain=video_position`과 영상 시각을 사용한다. 두 영상의 시작 시점 차이는 따로 맞춘다.
- **현재 예제.** `multiview.py live --jsonl`은 RGB 검출을 `detector_frame`에, 좌석 관측과 융합을 각각 `observations`, `fusion`에 기록한다. 공통 3D 좌표가 필요한 실험은 `main.py --serials … --stereo … --jsonl …` 경로를 쓴다. 같은 카메라로 두 프로그램을 동시에 실행하지 않는다.
- **보정·추적 → 판단.** 다음 형식을 세 팀원의 첫 합의안으로 쓴다. 한 관측에 좌석 번호, 관측 시각, 사람과 짐 각각의 존재 여부(true/false/null), 참여한 카메라, 가림·누락 여부를 담는다. 식별 가능한 경우에만 익명 사람/짐 트랙과 연관 후보를 추가한다. 예를 들어 A석의 T1이 B석에 가방을 두면 A에는 착석, B에는 짐과 T1 연관 후보가 남는다. T1은 학번이나 예약자 ID와 별개다. 장치 단절 중 경과한 시간으로 빈자리 증거나 부재 시간을 쌓지 않는다.

### 팀원에게 전달할 프롬프트 1 · 캘리브레이션과 추적

> SeatSense의 보정·추적을 맡아 줘. Windows에서 저장소의 `computer_vision_term/stereo_board.py`, `stereo_geometry.py`, `multiview.py`, `seat_fusion.py`와 관련 테스트를 먼저 읽어. 첫 산출물은 팀이 재사용할 보정 파일과 별도 자세로 측정한 검증 CSV야. 앞뒤 카메라를 최종 위치에 고정해 같은 보드 인쇄면을 촬영하고, 두 영상에서 A와 B가 가리키는 실제 교차점이 각각 같은지 확인해. 공장 내부 파라미터를 사용해 카메라 2의 점을 카메라 1 기준으로 변환하고 재투영 오차(px), 독립 자세의 3D 오차(mm)를 보고해. 카메라별 상판·의자 영역은 같은 실제 좌석 번호에 등록해.
>
> 다음은 건우의 두 카메라 검출 로그를 재생해 카메라별 사람·짐 트랙을 만들고 같은 물체를 대응해. 시간 차이, 클래스, 유효한 공통 3D 위치와 이동 이력을 사용해. 호모그래피는 상판에 쓰고, 깊이 누락이나 사람이 교차해서 대응이 애매한 경우는 미확정으로 전달해. 한쪽 시야가 가려졌을 때 반대쪽 관측과 이전 궤적을 사용해 기존 트랙이 이어지는지 확인해. 사람이 가방을 옆 좌석에 놓는 경우 거리·함께 이동한 이력으로 연관 후보를 남겨. 좌석별 착석과 짐 존재를 분리해서 판단 담당에게 보내 줘.
>
> 같은 구간의 앞 카메라 단독, 뒤 카메라 단독, 두 대 융합 결과를 정답과 비교해. 가림 중 누락·좌석 오판, 중복 트랙·ID 변경, 인접 가방 연관 성공/전체 건수를 표로 남겨. Windows와 Ubuntu에서 같은 입력 로그로 재현할 명령, 예시 출력, 실패 장면 한 건까지 넘겨 줘.

### 팀원에게 전달할 프롬프트 2 · 판단 알고리즘과 앱·LED

> SeatSense의 좌석 판단과 실시간 출력 통합을 맡아 줘. 저장소 루트 `app.py`, `static/`, `templates/`와 `computer_vision_term/demo_local.py`, `multiview.py`의 `SeatApp`을 먼저 읽어. 보정 완료를 기다리지 말고 모의 예약 DB와 시간순 좌석 관측으로 먼저 구현해. 지금 앱은 `POST /api/action`의 `action=detect`로 사람과 짐의 불리언 값을 받고 `/api/live`로 갱신해. 불확실한 관측과 센서 단절을 처리할 때는 마지막 확정 관측의 시각도 확인해. 누락을 빈자리로 기록하거나 오래된 관측으로 반납 처리하면 안 돼.
>
> 모의 예약과 실제 점유를 독립적으로 관리해. 정상 착석, 미예약 착석 후 잠깐 이석·복귀, 인접 좌석의 짐, 예약 만료 후 계속 착석, 사람과 짐이 모두 떠난 경우를 상태 전이표와 재생 테스트로 만들어. 장기 부재 기준은 제안서의 연속 1시간이고, 시연용 단축값과 퇴실 확인 시간은 별도로 설정해. 예약 반납과 새 예약을 받아도 되는지는 각각 판단해. 짐이 남거나 관측이 불확실하면 좌석을 즉시 개방하지 말고, 미예약 이용 중 예약이 완료되면 화면과 LED를 함께 갱신해.
>
> 학생·비로그인 화면은 예약 가능/이용 중, 관리자 화면은 예약 가능/이용 중/미예약 이용 중/반납 대기 중으로 표시해. 세부 매핑과 LED 색은 팀이 확정할 수 있게 표로 분리해. 미예약 착석 시 해당 좌석 LED로 예약을 안내해. 우선 모의 LED로 명령을 확인하고 실제 ESP32 전송 방식은 하드웨어 담당과 합의해. 같은 이벤트가 중복되거나 늦게 와도 이중 반납되지 않게 해. 실제 학교 서버 대신 SeatSense 모의 예약 DB를 써.
>
> 완료 시 입력 관측 → DB 상태 → 웹 표시 → LED 결과를 같은 시나리오에서 보여 줘. 1시간 경계 전후와 중간 복귀는 재생 시각으로 시험해. 잘못된 자동 반납·예약 허용 건수와 웹·LED 갱신 지연을 각각 기록해. 축소 모형에서는 관리 기능을, 실제 영상에서는 검출·추적 성능을 검증해.

### 팀 공통 평가

같은 정답 영상에서 단일/이중 카메라 및 프레임별 검출/추적·시간 유지 적용 결과를 비교한다. 제안서 목표는 **좌석 점유 정확도 90% 이상, 미예약 점유 F1 0.90 이상, 사람·소지품 구별 정확도 85% 이상**이다. 미확정 비율도 함께 기록해 판정을 자주 보류한 실험의 정확도가 과대평가되지 않게 한다. 결과표에는 거리·시점·조명·가림 조건, 사례 수, 측정 지연을 남긴다.

### 촬영 현장에서 코너 번호 확인하기

스티커를 보드 한쪽 모서리의 흰 여백에 고정한다. 14×10 내부 코너의 A는 0번, B는 13번이다. **현재 정지한 한 쌍 안에서** 왼쪽 A와 오른쪽 A가 같은 실제 점이고, 양쪽 B도 같은 실제 점이어야 한다. 스티커에 가장 가까운 점이 왼쪽 126번, 오른쪽 13번이면 `2`로 오른쪽 번호를 뒤집고 재확인한다. 양쪽 번호가 함께 뒤집혀 같은 물리적 코너끼리 대응되면 그 쌍을 쓸 수 있다. 줄 색을 20장 내내 통일할 필요는 없다. 촬영을 시작할 때 스티커 근처 실제 점을 A로 정해 두면 매번 확인하기 쉽다.

### Windows 개발과 Ubuntu 인수

저장소 최상위에서 운영체제별 가상환경을 만든다. 프로젝트 파일은 상대경로나 `pathlib.Path`로 찾고, 카메라 식별에는 SDK 시리얼을 쓴다. 패키지를 설치한 가상환경을 활성화한 뒤 아래 명령으로 카메라 없이 임시 예약 DB와 모의 입력을 함께 실행할 수 있다.

```powershell
python computer_vision_term/demo_local.py --app . --flask-python python
```

같은 저장 로그를 양쪽 OS에서 재생하여 좌석별 결과를 대조한다. Ubuntu 최종 인수에서는 USB 3 연결과 두 스트림 FPS·누락, 보정 오차, 실제 LED 포트와 권한을 확인한다. 두 카메라의 상대 배치가 바뀌면 외부 보정을 다시 하고 좌석과 카메라의 위치 관계가 바뀌면 ROI·빈 상판 참조도 갱신한다.
