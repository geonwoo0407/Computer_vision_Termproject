# 열람실 좌석 관리 · Flask 발표용 웹앱

## Ubuntu에서 실행

```bash
python3 -m venv .venv-linux
source .venv-linux/bin/activate
pip install -r requirements.txt
export SEAT_ADMIN_PASSWORD='개발용 관리자 비밀번호'
python app.py
```

브라우저에서 `http://127.0.0.1:5000`을 엽니다.

## Render에 시험 배포

이 프로젝트에는 Render 배포 설정인 `render.yaml`이 포함되어 있습니다. 배포하면
PC를 끈 상태에서도 Render가 제공한 HTTPS 주소로 휴대폰에서 접속할 수 있습니다.

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/geonwoo0407/Computer_vision_Termproject)

1. 위 **Deploy to Render** 버튼을 누르거나 Render Dashboard에서
   **New > Blueprint**를 선택하고 `Computer_vision_Termproject` 저장소를 연결합니다.
   `.gitignore`에 의해 가상환경, 로컬 SQLite DB, 세션 비밀키는 업로드되지 않습니다.
2. Blueprint가 `render.yaml`을 읽으면 `SEAT_ADMIN_PASSWORD`에 관리자 화면에서
   사용할 새 비밀번호를 입력합니다. 이 값은 코드나 GitHub에 적지 않습니다.
3. 배포가 끝나면 표시되는 `https://...onrender.com` 주소를 휴대폰에서 엽니다.
   학생 화면은 `/`, 관리자 화면은 `/admin`, 시연 화면은 `/demo`입니다.
4. `/admin`과 `/demo`의 사용자 이름은 `admin`, 비밀번호는 2단계에서 입력한
   `SEAT_ADMIN_PASSWORD`입니다.

Render 무료 Web Service는 시험용입니다. 일정 시간 요청이 없으면 정지되어 첫 접속이
느릴 수 있고, 재시작·재배포 때 로컬 SQLite 데이터가 초기화될 수 있습니다. 따라서
이 배포에서는 휴대폰 독립 접속과 화면/API 동작만 확인합니다. 실제 예약 데이터를
보존하는 운영 단계에서는 PostgreSQL로 이전하거나 유료 Persistent Disk를 붙이고
`SEAT_DATABASE=/var/data/seats.db`를 설정해야 합니다.

## 기존 VS Code 프로젝트에 적용 (Windows)
1. 기존 폴더를 백업합니다. 이 ZIP을 별도 폴더에 풉니다.
2. 기존 프로젝트의 app.py가 있는 위치에 ZIP의 내용을 모두 덮어쓰세요. 기존 .venv는 삭제하지 않습니다.
3. VS Code에서 프로젝트 폴더를 열고 터미널을 실행합니다.

기존 가상환경 사용:
```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```
새 폴더에서 시작한다면 먼저:
```powershell
py -m venv .venv
```
4. 브라우저에서 http://127.0.0.1:5000 을 엽니다.
학생: / · 관리자: /admin · 시연: /demo
서버 종료는 터미널에서 Ctrl+C.
휴대폰은 통신 가능한 같은 Wi-Fi에 연결하고 http://노트북IPv4주소:5000 으로 접속합니다. Windows ipconfig에서 주소를 확인합니다. 필요하면 개인 네트워크에서 Python 방화벽 접근을 허용합니다. 학교 Wi-Fi는 기기 간 통신이 제한될 수 있습니다.

## 관리자 인증과 데이터 보존

서버를 시작하기 전에 같은 PowerShell 창에서 다음 명령으로 관리자 비밀번호를 지정합니다. /admin 또는 /demo에서 사용자 이름 admin과 지정한 비밀번호로 접속하세요. 관리자용 API를 직접 호출할 때는 HTTPS에서 HTTP Basic 인증을 함께 보냅니다. 아래 카메라 입력 예제에도 인증이 필요합니다.

```powershell
$env:SEAT_ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', (Read-Host '관리자 비밀번호' -AsSecureString)).Password
```

기존 서버를 중지하고 instance 폴더를 백업한 뒤 실행하면 예약 이력(reservations)과 요청 결과(receipts) 테이블이 자동 생성됩니다. 기존 활성 좌석은 그대로 가져오며 알 수 없는 과거 생성·변경 시각은 비워 둡니다. 운영 환경은 지속 저장되는 DB와 같은 서명 키 파일을 사용하고 HTTPS와 SSE 스트리밍을 지원해야 합니다. 사용자별 쿠키가 다른 기기는 각각 별개 이용자입니다. 쿠키를 삭제한 경우 관리자가 새 이용자 ID로 예약자를 지정할 수 있습니다.

## 구현 범위
학생/관리자/시연 화면은 같은 SQLite DB를 사용합니다. 서버가 SSE(/api/live)로 변경된 상태를 각 접속자에게 전달하고, 연결 복구 시 1초부터 최대 30초까지 간격을 늘려 재시도합니다. 새로고침과 서버 재시작 후에도 데이터와 부재 시작 시각이 유지됩니다. instance/seats.db는 첫 실행 때 생성됩니다.
가운데 통로 양쪽에 2열 × 3행씩 12석을 배치합니다. 좌석 번호는 1~12입니다. 파랑=빈자리, 빨강=예약, 주황=미예약 이용입니다. 예약했지만 아직 착석하지 않은 경우 빨강+입실 대기로 구분합니다.
브라우저 쿠키로 이용자를 식별하고 학생 예약 취소/반납 API에서 소유권을 검증합니다. 학생은 서명된 익명 세션을 사용합니다. 관리 및 시연 작업은 관리자 인증이 필요합니다.
관리자 예약 부여/예약자 지정 시 대상 학생 화면의 이용자 ID를 입력할 수 있습니다. 권한 해제는 기존처럼 관리자가 수행할 수 있습니다.
카메라 인식, 사람 추적, 짐 귀속 판단, LED 출력은 구현하지 않았습니다. warning은 향후 LED 제어에 사용할 논리값이며 실제 점등을 의미하지 않습니다.

## 상태 판정
- reserved, occupied, belongings, used(이전 이용 이력), away_since를 독립 저장합니다.
- 사람이 감지되면 used=true, 자리비움 타이머 해제.
- 사람이 없고 이전 이용 이력이 있으며 (예약 또는 짐 있음)이면 자리비움. 반복 입력에도 시작 시각 유지.
- 미예약이고 사람/짐이 모두 없으면 퇴실: 이용 이력과 타이머 초기화.
- 이용 이력 없이 짐만 감지되면 주황색 '짐만 감지 · 확인 필요'. 자리비움으로 단정하지 않습니다.
- 예약 취소/권한 해제 시 사람이 있거나 짐이 남으면 주황색으로 전환. 실제 감지 정보는 지우지 않습니다.
- 예약자도 이용 후 완전히 떠난 경우 반납을 해야 빈자리가 됩니다.

## 시연 순서
1. /demo에서 시연 모드 선택 → 전체 초기화.
2. 학생 화면에서 1번 예약 → 시연에서 1번 '착석 + 짐': 빨강.
3. '사람 없음 + 짐': 빨강 유지 + 양쪽 화면에 타이머.
4. 2번은 예약 없이 착석: 주황 + 경고.
5. 2번 '사람 없음 + 짐': 주황 + 타이머.
6. 2번 '사람·짐 없음': 파랑 + 경고 해제.
7. 관리자로 미예약 이용 좌석에 예약 권한 부여/해제: 색상 전환 확인.

## 카메라 프로그램용 API
GET /api/seats : seats, mode, server_time 반환. 시각은 Unix 초입니다.
POST /api/action : JSON 객체. 모든 변경은 SQLite 트랜잭션으로 직렬화합니다.

카메라 입력을 쓰려면 /demo에서 '카메라 API 모드'로 전환합니다. 자동으로 카메라를 연결하거나 인식을 시작하는 기능은 아닙니다.
```python
import json, urllib.request
payload = {'action':'detect', 'source':'camera', 'seat_id':1,
           'occupied':True, 'belongings':False}
req = urllib.request.Request('http://127.0.0.1:5000/api/action',
    data=json.dumps(payload).encode(), headers={'Content-Type':'application/json'})
with urllib.request.urlopen(req) as response:
    print(response.read().decode())
```
seat_id는 1~12 정수. occupied와 belongings는 반드시 JSON true/false.
카메라 프로그램에서 순간적인 오검출을 안정화한 결과를 보내야 합니다. 서버는 받은 결과를 즉시 적용합니다. 입력 중단 시 마지막 상태를 유지하고 관리자에 마지막 입력 시각을 표시합니다.
belongings는 해당 좌석에 귀속된 짐의 유무입니다. 옆자리에 둔 짐의 소유자를 판단하는 처리는 향후 카메라 프로그램에서 수행합니다.
다른 동작: reserve/cancel/return/move(학생), grant/revoke/assign_owner(관리자), mode(mode:demo 또는 camera), reset(시연 모드만).
200=성공, 400=잘못된 입력, 404=없는 좌석, 409=예약 충돌/모드 충돌.
입력 모드는 중복 입력 방지용이며 보안 인증 수단이 아닙니다. 네트워크 지연으로 순서가 뒤바뀌지 않도록 카메라 클라이언트는 요청을 순차 전송하세요.

## 반납 업데이트 적용 (데이터 유지)
1. 실행 중인 서버를 Ctrl+C로 종료합니다.
2. 기존 프로젝트 전체를 백업합니다. 특히 instance 폴더를 보존하세요.
3. ZIP 파일을 **기존 프로젝트 폴더에 덮어씁니다**. 기존 폴더를 삭제하거나 새 폴더에서 실행하지 마세요.
4. .venv 및 instance 폴더는 삭제하지 않습니다. ZIP에는 DB, 비밀키, 가상환경이 들어 있지 않습니다.
5. 기존 방식으로 서버를 다시 실행하고 브라우저에서 Ctrl+F5로 새로고침합니다.

첫 실행 시 기존 seats 테이블에 누락된 좌석(7~12번)과 소유자 열을 추가하고 visitors, reservation_events 테이블을 생성합니다. 기존 예약, 감지 상태, used 및 away_since를 덮어쓰거나 초기화하지 않습니다. 변경 이후 예약·취소·반납·관리자 작업은 reservation_events에 별도 보관됩니다. 업데이트 전 과거 이벤트는 원본에 기록되지 않았으므로 복원하지 않습니다.
instance/seats.db.secret은 쿠키 서명을 위한 새 파일이며 자동 생성됩니다. 서버 재시작 이후 같은 이용자로 유지하려면 DB와 함께 보존하세요. 쿠키 삭제/시크릿 창/다른 브라우저는 다른 이용자입니다.

### 본인 예약과 기존 예약
- 학생 화면에 내 이용자 ID가 표시됩니다. 같은 브라우저 탭들은 동일한 이용자입니다.
- 새 학생 예약은 현재 이용자 소유로 저장됩니다. 다른 이용자는 학생 화면/API에서 취소·반납할 수 없습니다.
- 소유자가 기록되지 않은 구버전 예약만 미지정 상태로 유지됩니다. 관리자의 '예약자 지정'에서 학생 화면의 이용자 ID를 입력하세요. 예약이나 타이머를 해제할 필요가 없습니다.
- 관리자의 예약 부여도 대상 ID를 입력합니다. 시연 화면의 예약 부여는 현재 브라우저 이용자에게 부여합니다.

### 예약 취소 / 반납하기
- 예약 취소: 본인 예약 중 아직 이용 이력(used)이 없는 좌석에서 제공됩니다.
- 반납하기: 본인이 예약한 좌석에 표시됩니다. 확인 창에서 확인해야 예약 권한이 해제됩니다.
- 반납은 감지값이나 소지품 귀속, 기존 부재 타이머를 임의로 삭제하지 않습니다.
- 사람 있음 → 주황색. 사람 없음 + 짐 있음 + 이용 이력 있음 → 주황색 자리비움(기존 타이머 유지).
- 사람 없음 + 짐 있음 + 이용 이력 없음 → 주황색 '짐만 감지 · 확인 필요'.
- 사람·짐 없음 → 파랑. 반납 후 나중에 이 감지 결과가 들어와도 자동 퇴실 처리됩니다.
- 감지는 마지막 API 입력을 기준으로 판단하며 실제 카메라가 연결된 것은 아닙니다.

### 소지품 귀속 정보
기존 belongings는 **해당 좌석에 귀속되었거나 귀속을 아직 확인해야 하는 짐의 존재**를 뜻합니다. 반납한다고 짐 정보를 없애지 않습니다. detect 입력에 선택적으로 belongings_owner_id(추적 프로그램의 소유자 문자열 ID 또는 null)를 보낼 수 있습니다. 이 ID는 앱의 브라우저 이용자 ID와 자동 연결하지 않으며, 짐을 옮기거나 주인을 추론하는 알고리즘도 아닙니다. 사람·짐이 모두 없다는 입력에서만 소지품 소유 정보도 해제합니다. 소유자가 불명확해도 짐이 있으면 빈자리로 처리하지 않습니다. 옆자리에 놓인 짐을 소유자의 원래 좌석에 귀속시키는 판단은 외부 카메라 프로그램이 담당합니다.

### 반납 시연
1. 학생 화면에서 1번 예약 → 반납하기 표시 확인.
2. 다른 브라우저/시크릿 창에서 같은 주소 접속 → 1번 반납 버튼이 없는지 확인.
3. 같은 브라우저의 /demo에서 1번 착석 + 짐 → 학생 화면에서 반납 확인 취소 → 예약 유지.
4. 다시 반납 확인 → 주황색. /admin에서도 같은 상태 확인.
5. 시연에서 사람 없음 + 짐 → 주황 + 타이머, 사람·짐 없음 → 자동 파랑.
6. 다시 예약/착석/자리비움 후 반납 → 타이머 시작 시각과 짐 정보 유지 확인.

### 자리 이동과 동시 접속
내 좌석 → 자리 이동 → 빈 책상 선택 → 해당 좌석으로 이동을 누릅니다. 학생 1명(브라우저 ID)당 신규 예약은 1석입니다. 이동은 한 트랜잭션에서 원래 예약 해제와 목적지 예약을 처리합니다. 다른 사람이 먼저 목적지를 차지하면 기존 예약은 유지됩니다. 원래 좌석의 사람·짐·타이머는 그 자리에 남습니다.
API 예: {"action":"move","seat_id":1,"target_id":12}. 예약 주인이 다르면 403, 목적지 선점이면 409입니다.
두 사람을 시연하려면 일반 창과 시크릿 창 또는 서로 다른 기기를 사용합니다. 동일한 서버 주소를 열고 한쪽에서 예약·이동한 다음 상대 화면에서 새로고침 없이 확인합니다. 폰 두 대 모두 노트북 서버에 접근할 수 있어야 합니다.


## PWA 설치 안내
프로젝트에 manifest, 앱 아이콘, 설치 스크립트와 service worker를 추가했습니다. 앱을 여는 화면은 설치돼도 좌석 조회/예약은 Flask 서버가 켜져 있고 네트워크에 연결돼야 작동합니다. 학생 시작 화면과 정적 파일을 오프라인 보관하며 좌석 데이터/기능은 오프라인에서 동작하지 않습니다.

휴대폰에 설치하려면 모바일 브라우저에서 앱에 HTTPS 주소로 접속해야 합니다. 같은 Wi-Fi에서 노트북 주소 http://노트북IP:5000 으로 접속하는 방식은 개발 테스트에는 쓸 수 있지만, 휴대폰에서 service worker가 필요한 PWA 설치 조건을 만족하지 않을 수 있습니다. 이 경우 HTTPS 주소로 배포하거나 안전한 HTTPS 터널을 준비해야 합니다. 앱을 어디서나 쓰게 하려면 Flask 서버와 SQLite DB를 인터넷에서 계속 실행되는 호스팅으로 옮깁니다. 무료 호스팅은 파일 시스템이 초기화될 수 있으므로 SQLite 지속 저장 지원을 먼저 확인하세요.

- Android/Chrome: HTTPS 접속 후 화면의 '앱 설치' 버튼 또는 브라우저 메뉴의 '앱 설치'를 선택합니다.
- iPhone/Safari: 공유 메뉴 → '홈 화면에 추가'를 선택합니다. 홈 화면에 추가 옵션이 표시되지 않으면 HTTPS로 접속했는지 확인합니다.
- 로컬 확인: PC 브라우저의 http://127.0.0.1:5000 은 localhost 예외로 service worker 등록을 확인할 수 있습니다. 휴대폰의 localhost는 휴대폰 자신을 가리키므로 노트북 서버 주소로 사용하지 않습니다.
